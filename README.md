# 日常工具 Dashboard

自己的工具目錄：搜尋、分類、狀態篩選、常用釘選，以及各工具的入口與啟動說明。

第一版收錄日常工具目錄原有的 8 個工具，另設 Playground 入口。工具資訊來自既有專案文件；所有使用狀態先標為「待確認」。新增空資料夾不會自動成為工具。

## 如何啟動

這是 Mac 本機版，需要 Node.js 22 以上，不需要安裝 npm 套件。

1. 在 Finder 開啟此資料夾。
2. 雙擊 [啟動日常工具.command](啟動日常工具.command)。
3. 程式會開啟 [日常工具 Dashboard](http://127.0.0.1:4318/)。

終端機視窗需保持開啟；按 Control+C 停止。重複開啟啟動檔時，如果本目錄的服務已在執行，會沿用既有服務。若連接埠被其他程式占用，會顯示訊息並停止，不會關閉其他程式或任意換網址。

也可在本資料夾的終端機執行：

```sh
npm start
```

請透過啟動程式或上述指令使用，不直接雙擊 `dist/index.html`；瀏覽器以檔案方式開啟時，通常無法讀取 JSON 工具清單。

## 怎麼使用

- 輸入工具名稱、別名或用途搜尋，例如「財務」「日積」都能找到財務工具。
- 左側選分類，可再搭配狀態篩選；重按分類可取消該分類。
- 卡片的星號用於釘選；常用工具會在總覽優先顯示，也可由左側單獨查看。
- 「開啟網站」連到已登錄的線上網址；「啟動說明」顯示本機工具的前置步驟。
- 「詳情」包含專案位置、README 路徑、下一步與資訊來源。
- 「Playground」顯示實驗資料夾位置與練習方式。
- 鍵盤按 `/` 將焦點移到搜尋；詳情視窗可用 Escape 關閉。

複製啟動指令只會放到剪貼簿，不會執行。不能複製時會提供可選取文字。複製路徑後可在 Finder 按 ⇧⌘G 前往。

## 工具資料與新增方式

[dist/tools.json](dist/tools.json) 是工具目錄的唯一資料來源。更改後重新整理網頁即可，不需要建置。

新增工具：

1. 複製清單內一個相近工具的物件，加入 `tools` 陣列。
2. 改成新的唯一 `id`，填入名稱、用途、分類與資料夾相對路徑。
3. 填入真實入口與來源。未知的 README、下一步、核對日期填 `null`；沒有入口時使用 `launches: []`。
4. 有入口時，恰好指定一個 `primary: true`；線上入口用 HTTPS。
5. 在此資料夾執行 `npm test`，再執行 `npm run sync:overview`，讓上一層 README 的表格一併更新。

常用欄位：

| 欄位 | 說明 |
| --- | --- |
| `id` | 穩定的工具識別碼，例如 `finance`；修改名稱時保留 |
| `name` / `alias` | 資料夾對應的工具名稱與顯示別名 |
| `category` | 工作學習、生活管理、旅行文化、媒體、開發練習 |
| `status` | 待確認、開發中、使用中、暫停；由自己核對後修改 |
| `projectPath` / `readmePath` | 相對於日常工具總目錄的路徑 |
| `launches` | `web`：線上網址；`instructions`：啟動步驟；`file`：本機檔案 |
| `command` / `cwd` | 指令與工作目錄成對記錄；第一次安裝放在 `steps` |
| `lastReviewedAt` | 實際核對文件的日期，不是服務在線時間 |

`workspaceRoot` 是這台 Mac 的日常工具根目錄，供顯示與複製完整路徑。日後整個目錄搬家時更新它。完整欄位與第一版設計見 [規劃書](../DASHBOARD_PLAN.md)。

## 資料保存與備份

- 工具目錄：保存於 `dist/tools.json`，可由本專案 Git 管理與回復。
- 常用釘選：保存在目前瀏覽器、目前網址的 localStorage，鍵名 `daily-tools.pins.v1`。換瀏覽器、換網址或清除瀏覽器資料後不會自動同步。
- 釘選只是偏好，不影響工具是否存在；第一版尚無釘選匯出功能，遺失時可以重新釘選。
- 各工具的帳本、運動紀錄、照片等仍由各工具自己保存與備份；此 Dashboard 不讀取這些內容。
- 瀏覽器儲存不可用時仍能操作工具，畫面會說明釘選可能無法保留。

## 檔案分工與學習路線

```text
dashboard/
├── README.md                 使用、維護與學習說明
├── 啟動日常工具.command       Mac 雙擊啟動入口
├── server.mjs                只提供 dist 目錄的本機 HTTP 服務
├── package.json              啟動、檢查與同步指令
├── dist/                     直接維護的網頁原始檔，納入 Git
│   ├── index.html            頁面結構與可操作控制項
│   ├── styles.css            桌面與手機排版
│   ├── tools.json            工具目錄資料
│   ├── catalog.mjs           資料驗證、篩選與釘選保存
│   └── app.mjs               卡片、詳情、事件與畫面狀態
├── scripts/sync-overview.mjs  由同一清單產生上一層工具表格
└── tests/catalog.test.mjs     核心行為與失敗情境檢查
```

`dist/` 在這個簡單靜態專案中就是直接編輯的原始檔，不是可以刪掉重建的產物。

資料流：`tools.json → 驗證 → 依條件篩選 → 顯示卡片`。點星號則更新釘選集合、保存到瀏覽器，再重新顯示清單。

可以依序練習：

1. 只改一個工具的描述，觀察「資料與畫面分開」的好處。
2. 看 `filterTools` 如何組合搜尋、分類與狀態。
3. 看 `setPinned` 如何讓畫面狀態與儲存同步。
4. 改一個小地方，查看 Git 差異，完成後再保存版本。

## 驗證

```sh
npm test
node --check dist/app.mjs
npm run sync:overview
```

目前自動檢查涵蓋資料與路徑、組合篩選、缺少入口、重複識別碼、錯誤連結、釘選讀寫，以及儲存不可用時的退回行為。

瀏覽器檢查紀錄與後續待辦見 [規劃書](../DASHBOARD_PLAN.md#第一版驗收)。

## 目前限制與下一步

- 目前只綁定 `127.0.0.1:4318`，供這台 Mac 使用；雖有手機版排版，手機還不能透過此網址連到 Mac。
- 未部署網站。各工具線上入口取自文件，不代表已在本次驗證其服務可用性。
- 第一版透過 JSON 維護目錄，尚無新增／編輯工具的表單，也不自動掃描資料夾。
- 一般網頁無法直接啟動 Mac 程式；第一版提供入口或操作說明。
- 旅行日記尚缺 README 與常用入口；問答工具線上入口待登錄。
- 下一步先使用一週，記錄「找不到、開不了、資訊不清楚」的具體情境，再決定需要新增的功能。

支援 WebMCP 的瀏覽器可使用與畫面共用邏輯的搜尋、釘選工具；不支援時不影響網頁操作。
